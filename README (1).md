# HIV Care & Risk Analytics Platform

An end-to-end demo of a health-analytics pipeline: ingesting data from multiple sources, centralizing it in a database, analyzing and modeling it, and serving the results through a live dashboard and API.

Built as a survey project to cover a broad range of the data/ML stack — from raw data ingestion through to a deployed backend microservice — using synthetic patient data.

## What it does

The pipeline is organized in five phases:

1. **Data Ingestion** — pulls data from a public API, scrapes headlines from a web page (BeautifulSoup), and reads/writes legacy Excel records (pandas).
2. **Centralized Storage** — loads the ingested data into a SQLite database and queries it with SQL.
3. **Analysis & Modeling**
   - Statistical significance testing (SciPy t-test)
   - Interactive data exploration (D-Tale)
   - Machine learning risk classification (scikit-learn Random Forest)
   - A small neural network for the same task (PyTorch)
   - NLP sentiment scoring on sample text (TextBlob)
   - Resource-allocation optimization (PuLP)
   - Network graph of patient–clinic relationships (NetworkX)
4. **Visualization & Reporting** — an interactive map (Folium), automated text/HTML report generation, and a live dashboard (Streamlit).
5. **Serving Predictions** — a Flask microservice that exposes a `/api/risk` endpoint, plus a client example that sends patient data to it and prints the response.

## Tech stack

`Python` · `Jupyter Lab` · `pandas` · `requests` / `BeautifulSoup` · `SQLite` · `SciPy` · `scikit-learn` · `PyTorch` · `TextBlob` · `PuLP` · `NetworkX` · `Folium` · `Streamlit` · `Flask`

## Running it

```bash
pip install requests beautifulsoup4 pandas openpyxl sqlalchemy scipy scikit-learn torch textblob pulp networkx matplotlib numpy folium streamlit flask dtale
```

Run the notebook top to bottom. Two components run outside the main notebook flow:

- **Dashboard:** `streamlit run dashboard.py` (generated by the notebook)
- **Backend API:** started automatically in a background thread on `http://127.0.0.1:5001`; test it by POSTing patient data to `/api/risk`

## Notes

- All patient records are synthetic/mock data generated for demonstration — no real clinical or personal data is used.
- The hardware-integration section (pySerial smart pillbox) is a framework only and requires a physical microcontroller to run.
- This project prioritizes breadth (demonstrating the full pipeline) over production hardening — see `project_cleaned.ipynb` for the annotated walkthrough of each stage.
